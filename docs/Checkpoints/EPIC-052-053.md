## The defect this Epic found in the last one

**60 of 61 commits held nothing but a SHA.** `git log` returns commits newest
first, each emitting its parent as a placeholder before the loop reaches that
parent properly — and the placeholder won. Every commit that is a parent of a
newer one lost its message, author, dates and tree.

Nothing failed. The graph had exactly the right shape and was almost entirely
empty, and every structural assertion in nineteen Epics still passed — **because
every one of them checked shape**. It took the first test that asserted *content*
("find a commit by words from its message") to see it.

## Notes for whoever picks this up

- **Keep exact and full-text apart.** An exact question gets an exact answer or
  none. Returning a ranked approximation to "which files does this repository
  contain" is worse than returning nothing, because the caller cannot tell.
- **Everything is a bind parameter, including attribute names.** Nothing in
  `retrieval.ts` is concatenated into SQL.
- **Raw `execute` does not run Drizzle's column parsers.** Timestamps come back
  as strings; use the `instant()` helper.
- **`ts_rank` is comparable within one result set and nowhere else.**
- **Paths are indexed twice**, raw and separator-translated, because PostgreSQL
  lexes `src/retry-policy.ts` as one token.
