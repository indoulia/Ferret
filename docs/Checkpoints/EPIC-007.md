## Completed

- **26 typed, directed relationship types**, each declaring the entity kinds it
  may connect — which makes "branch and worktree relationships stay distinct" a
  rule rather than a convention.
- **Bitemporal storage.** Valid time (`valid_from`/`valid_to`) separate from
  index time (`first_indexed_at`/`last_indexed_at`).
- **Half-open intervals**, so a handover instant has exactly one answer.
- **Exclusive types** — a branch points at one commit — with correct interval
  reconciliation under any arrival order.
- **Idempotent assertion**: identity includes `validFrom`, enforced by a unique
  index.
- **Retire as a tombstone**; nothing is deleted.
- **Traversal primitives**: `outgoing`, `incoming`, `neighbours`, `history`, each
  with type and point-in-time filters.
- **An extensible type registry**, matching the entity-kind contract.
- **Migration 0004**, generated by drizzle-kit and reviewed.
- **A dedicated concurrency suite** covering the properties that span subsystems.

## Decisions

Full rationale in [`docs/Architecture/EPIC-007-DECISIONS.md`](../Architecture/EPIC-007-DECISIONS.md).

- **D-001** a table with indexes, not a graph database
- **D-002** relationships are bitemporal — two clocks, two questions
- **D-003** valid intervals are half-open, so a handover is unambiguous
- **D-004** identity includes `validFrom`, so an edge can recur
- **D-005** types declare the entity kinds they may connect
- **D-006** some types are exclusive from their source
- **D-007** exclusive assertions take a transaction-scoped advisory lock
- **D-008** out-of-order events are reconciled, not dropped
- **D-009** retiring closes, never deletes
- **D-010** self-loops are rejected
- **D-011** a checked-out `pg` client gets its own error handler

## Three defects these tests caught

1. **Write skew left eight open intervals** where one is permitted. Fixed by
   D-007. Invisible to single-threaded testing.
2. **The fix exposed an ordering bug**: the count fell to two, not one, because
   closing only *open* earlier intervals leaves gaps when events arrive out of
   order. Fixed by D-008, with a whole-table no-overlap invariant to keep it
   fixed.
3. **A `pg` client failing while checked out crashed the process.** Not an
   EPIC-007 concern — a live crash in shipped code, found by this Epic's test
   run and fixed here (D-011). A PostgreSQL restart would have killed the user's
   AI session rather than failing one query. The suite had been reporting it as
   an unhandled error *while still passing*.

## Notes for whoever picks this up

- **`RelationshipStore.#reconcileExclusive` is the subtle part.** Both of its
  rules are load-bearing, and rule (a) must include already-closed intervals —
  see D-008 for the case that proves it. The whole-table no-overlap assertion in
  `concurrency.test.ts` is the guard; do not weaken it.
- **The advisory lock key must stay `(fromId, type)`.** Keying on the type alone
  would serialize ingestion globally, and a test asserts it does not.
- **Adding a relationship type Ferret should ship:** add it to
  `RelationshipType` and to the `BUILT_IN` table in `src/domain/relationship.ts`,
  with its endpoint kinds and whether it is exclusive. Nothing else changes.
- **Adding a type a provider owns:** `registerRelationshipType`.
- **Any new code that holds a `pg` client across an `await`** inherits D-011's
  protection through `createPool`. Do not construct a bare `new Pool` elsewhere.

## Known limitations

Full table in the validation evidence. Carried forward:

- Reconciliation bounds an interval by the successor known at insert time; it
  does not re-derive the whole timeline
- Traversal is one hop → **EPIC-050**
- No relationship-level provenance beyond `sourceSystem`/`sourceId` → **EPIC-008**
- No confidence on inferred relationships → **EPIC-046**
- `retire` closes the most recent open interval, not an arbitrary historical one
- No depth or cycle protection, because traversal is one hop → **EPIC-050**
- macOS unvalidated → **EPIC-105**

## Next step

**EPIC-008 — Evidence & Provenance Model.** The substrate is in place: `evidence`
is already an entity kind, `EVIDENCE_SUPPORTS_ENTITY` is already a relationship
type, and both entities and relationships already carry their source system.

EPIC-008 needs to add the layer above that: what Ferret *observed* versus what it
*derived*, where in a source a fact was found, and how a derived answer traces
back. Note that two limitations recorded here are EPIC-008's to close —
relationship-level provenance, and the distinction between a
`commit_resolves_issue` parsed from a commit message and one from an API.

Then **EPIC-009** (Identity & Scope — build on `ferret.instance` from EPIC-002
migration 0001 rather than replacing it) and **EPIC-010** (Schema Versioning,
which owns the compatibility rules EPIC-006 D-014 defers to it). Those three
close the Canonical Knowledge Model domain.
